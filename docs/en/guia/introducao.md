# Introduction

Modux is a module framework for Roblox whose goal is to bring more power to your
typing, and which also hands you warnings and errors so you don't have to keep
running your code over and over just to find mistakes.

For example, if we put a basic value on `self`, it comes back with an
autogenerated type:

:::demo
```lua
--!strict
const Zombie = Modux.Controller("Zombie")

function Zombie:Heal(amount: number)
	self.Health = amount
end

Zombie.Health --> number
```	
:::
:::tip Tip:
Some things you don't need to hit play to see they'll break. Just type them!
:::

### Saving time
On top of `strict` and the backing of `typefunctions`, modux has `generic types`
for the controllers you create, plus a tool that turns your own functions, their
parameters and simple values on the self into typing inside a `Types.luau` file
generated within the module.

So, for instance, writing a `name as string` or an `age as number` onto `self`
makes it come back typed anywhere else that touches the self:
::: demo
```lua
const Zombie = Modux.Controller("Zombie")

function Zombie:Heal(amount: number)
	self.Name = "Joaquim"
	self.Age = 197
end

function Zombie:Test()
	self.Name --> string
	self.Age --> number
    self:Heal("Abc") --> Type Error: Expected number, got string
end 
```

### Require
The same goes for the requires you put in the head. Writing
`Require = { "Skeleton" }` types the Skeleton module inside your dependencies and
attaches its functions with autocomplete, parameters included:
::: demo
```lua
--!strict
const Skeleton = Modux.Controller("Skeleton")

function Skeleton:ShootArrow(Target: Instance)
end
```
:::
And in another module using it:
::: demo
```lua
--!strict
const Zombie = Modux.Controller("Zombie", { Require = { "Skeleton" } })

function Zombie:Heal(amount: number, target: Instance)
	self.Dependencies.Skeleton:ShootArrow(target) -- typed, and you wrote none of it
end
```

The biggest advantage is this: you didn't write a single type. Inside
Dependencies > `Skeleton` it shows you exactly which methods exist and which
parameters they take. Try to require something that doesn't exist and it calls
that out too!

The trick: a generator reads your modules and writes one type leaf per module.
The framework stitches those leaves together with Luau type functions. How that
works under the hood is in [How the typing works](/en/tipagem/).

And for components, let's go straight to a practical example with a `Highlight`:
::: demo
```lua
local ServerScriptService = game:GetService("ServerScriptService")
local Modux = require(ServerScriptService.server.Modux)

const Highlight = Modux.Component("Highlight")

Highlight:OnInit(function(self)
	local new = Instance.new("Highlight")
	new.Parent = self.Instance
	task.delay(5, function()
		self.Instance:Destroy()
	end)
end)

return Highlight

```
:::
With that, anything carrying the Highlight tag in Roblox is automatically bound
to this class and `OnInit` fires right away.

If you'd rather create a component from another class, though, don't add a tag —
use the `CreateComponent` method. See the
[Components](/en/arquitetura/componentes) section.

## Why use it?
Well, if automatic typing, a typed bootstrap and "cyclic" requires solved with
typed DI (Dependency Injection) still haven't sold you, just think about the work
it would be to write methods, parameters and self values all by hand, all the
time, keeping them in step with the real values and methods as they change.

That's the reason so many people give up on typing in Luau, and it's what makes
this tool perfect for everyone.

## Architecture

The framework's pieces — Controller, Service, Component, and how they wire
together — are in [Architecture](/en/arquitetura/).

## Known limits

**Scaling ceiling.** Somewhere between 100 and 150 modules **per side**, the
solver starts answering `Code is too complex to typecheck`. Since Controller and
Service live in separate Manifests, splitting by side nearly triples the
headroom. Five ways of reorganizing the types were measured and none that is
**usable** beat the current design — see
[Benchmarks](/en/benchmarks#where-the-cost-lives).

**No networking built in.** The framework stops you from crossing sides, but it
doesn't hand you the bridge. Networking comes in as a lib in
[`src/Libs`](/en/arquitetura/libs), not as part of the core.

### Benchmark
Measured, not estimated. The method, the environment and the full tables are on
[Benchmarks](/en/benchmarks) — including the comparison against Modux V2, where
the current design **loses** on analysis time.

| | |
|---|---|
| autocomplete, warm median at 100 modules | 0.9 ms |
| project `analyze`, 100 modules on one side | 19.5 s |
| the same 100 split between client and server | 9.1 s |
| generated surface per module, against V2 | 3.9× smaller |
| overhead per component, per frame (runtime) | 0.21 µs |

What costs is the batch `analyze`, which runs once per commit. While typing,
none of it is felt.

### Parser
The generator can't parse every lib, mostly when the value comes out of a
function call. When that happens, a `::` cast is all it takes to get the field
onto the self, typed.

::: demo
```lua
self.Life = 100                          -- becomes number
self.Orientation = CFrame.new() :: CFrame -- needs the annotation
```
:::
